# Miguk Story SEO Audit — 2026-05-27

## Executive summary

Miguk Story's core crawl foundation is mostly sound: public pages return `200`, robots.txt points to the sitemap, the sitemap excludes utility/auth pages, canonical URLs are present, and newly published posts are submitted through IndexNow/Google indexing workflows. The bigger visibility risk for a new Google site is not a single robots/sitemap blocker; it is the combination of low domain trust, broad topical spread, thin/news-rewrite content, and weak Search Console visibility into indexing exclusions.

## P0 — technical blockers / crawl hygiene

- **Sitemap foundation: PASS.** `astro.config.mjs` uses `@astrojs/sitemap`, filters `/admin/`, `/auth/`, `/login/`, `/subscribed/`, and `/404/`, and emits per-post `lastmod` from `updatedDate`/`pubDate` instead of fake build timestamps.
- **Indexability audit: PASS.** `npm run build` runs `scripts/audit_indexability.mjs`, which guards against noindex URLs leaking into the sitemap and broad noindex headers.
- **Draft leakage: fixed.** Published posts no longer contain `draft: true`; this audit adds a formal `draft` field to the content schema and filters RSS to `!data.draft` so a future draft cannot be advertised in RSS by accident.
- **Robots/canonical/RSS:** keep verifying after each deploy: `/robots.txt`, `/sitemap-index.xml`, `/sitemap-0.xml`, `/rss.xml`, and a fresh post URL.

## P1 — new-site Google visibility priorities

1. **Search Console access and reporting.** Connect GSC API/service account or OAuth with `webmasters.readonly` so we can see real indexed/excluded counts, queries, impressions, and pages. Do not rely on `site:` alone.
2. **Submit sitemap after deploy.** Continue the `Google Indexing` workflow and verify `Sitemap submit: 204 ✅` in logs after technical SEO changes.
3. **Reduce thin content exposure.** Current repo scan: 141 blog posts, 51 under roughly 450 words. For a new site, this can dilute quality signals. Rewrite, consolidate, noindex, or remove low-value off-topic rewrites rather than publishing more volume.
4. **Topical focus.** Immigration, tax, health insurance, education, retirement, real estate, and Korean-American community service content should be prioritized over generic world/travel/news items.
5. **Internal link clusters.** Build pillar pages for high-intent Korean-American topics and link supporting articles into those hubs.

## P2 — UX / performance / trust improvements

- **Mobile navigation:** login/search/contact actions should be visually obvious and tappable in the mobile drawer. The login CTA is now forced to high contrast with a dedicated selector so it is not overridden by the generic nav link color.
- **Blog archive weight:** `/blog/` currently exposes many posts in one archive. Add pagination or stronger category hubs so crawl equity is not diluted across a huge flat listing.
- **Schema and E-E-A-T:** keep author/source/editor note patterns on evergreen pieces; prioritize official sources and practical checklists.
- **Core Web Vitals:** run PageSpeed/Lighthouse when API quota allows; watch archive size, fonts, and large images.

## Safe fixes applied in this pass

- Mobile login CTA contrast/specificity in `Header.astro`.
- Formal `draft` schema field in `src/content.config.ts`.
- RSS now filters drafts and sorts newest-first in `src/pages/rss.xml.js`.

## What not to do

- Do not mass-publish generic short news rewrites to force freshness.
- Do not create fake backlinks or spammy directory submissions.
- Do not put login/admin/auth pages into the sitemap; they should remain discoverable only as utility noindex pages.
